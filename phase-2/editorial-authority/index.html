IIWebsite Design & Development

A website built to be found, understood, and trusted.

A good-looking site can still be invisible. Most of the problems we see are structural: pages that do not match what people search for, slow templates, duplicate URLs, missing structured data, and content no one can find from the home page.

We fix that at the foundation. Information architecture comes before visual design, and the technical work is built in from the first template, not added after launch.

Consult on the site you have

Ken inspects the existing site and writes down what is blocking search and conversion: structure, speed, indexing, page targeting, content gaps. You get a plain-English recommendation to fix or to rebuild, and what either would take.

Build or rebuild

Site structure, page templates, the core pages, and the technical foundation, launched on a real host and your own domain. Pages are built around what people actually search for, so the search work has something to stand on from day one.

Built into every site

  1. Information architecture One page per job, organized the way customers search.
  2. Performance Fast templates, compressed images, and nothing loaded that the page does not need.
  3. Accessibility Semantic markup, keyboard support, readable contrast, and motion that respects user settings.
  4. Technical SEO Clean URLs, self-referencing canonicals, sitemaps, and internal links that match them.
  5. Structured data Organization, Person, service, and breadcrumb data that describes real facts.
  6. Analytics foundations Measurement set up deliberately, with only what you need to make decisions.
  7. Conversion and trust Clear paths to contact, honest proof, and nothing that feels like a trap.
  8. Maintainability A handoff you can edit without us, documented in plain English.

IVSelected work

LuckyDomains.io: off Wix, onto a site the company owns

The company site moved from Wix to a hand-built static site on GitHub Pages, with the duplicate-URL problems fixed and every decision written down in a public repository.

The old site ran on Wix. It was small and dated, and it carried a recurring subscription for capability the business was not using. The owner wanted a site that was portable, versioned, and editable by coding agents.

Work completed

  • Moved the site from Wix to GitHub Pages on the apex domain, with HTTPS
  • Rewrote 93 internal links to one canonical form
  • Gave every page a self-referencing canonical tag that matches the sitemap
  • Kept old .html addresses as noindex stubs that point to the new URLs
  • Shared one Person identifier for the founder with kenashe.ai
  • Added a dependency-free test suite that runs on every push

No traffic, ranking, or lead figures are claimed for this project.

Read the case study

From the decision log

  1. 1Decision D1: retire Wix and serve a hand-built static site from GitHub Pages, on the company's own domain.
  2. 2Decision D4: every page linked to index.html three times, which told Google the duplicate was real. All 93 links now use one canonical form.
  3. 3Decision D11: old .html addresses stay as small noindex pages that point to the new URL, because a static host cannot redirect.
  4. 4Decision D8: a dependency-free test suite runs on every push, checking links, canonicals, the sitemap, and metadata.

VIHow AI changes the work

AI-powered execution with human accountability.

Lucky Domains uses AI and internal automation for the slow, repetitive parts of the job, so more of the time goes into judgment. Ken reviews and signs off on every recommendation.

  • Research. Domain candidates, competitors, and the questions customers actually ask.
  • Technical audits. Crawls, indexing checks, and canonical and duplicate-URL reviews.
  • Website QA. Links, metadata, accessibility, and performance checks on every change.
  • Structured-data review. Validation of Person, Organization, and service data against the facts.
  • Content architecture. Page maps built from real search demand.
  • Profile and citation research. Finding the profiles and sources that describe a brand, and where they disagree.
  • Implementation. Repetitive markup, redirects, and page updates, checked by tests.
  • Monitoring and reporting. Tracking changes over time and preparing plain-English reports.

Lucky Domains runs an internal agent that researches listing sites, creates profiles, and confirms its own verification emails. It is an internal system, not a client product.
