Case study · Website strategy and build

LuckyDomains.io: off Wix, onto a site the company owns

The company site moved from Wix to a hand-built static site on GitHub Pages, with the duplicate-URL problems fixed and every decision written down in a public repository.

Client
Lucky Domains (our own site)
Year
2026
Status
Live since June 2026
Layers
Website, Search, Entity

IProblem

A site the business did not own.

The old site ran on Wix. It was small and dated, and it carried a recurring subscription for capability the business was not using. The owner wanted a site that was portable, versioned, and editable by coding agents.

IIApproach

Plain files, the company's own domain.

Rebuild as plain static HTML with no framework and no build step, served from GitHub Pages on the company's own domain. Fix duplicate URLs with canonical tags and consistent internal links, because a static host cannot write server redirects.

Built and deployed with an AI agent, with the decisions recorded in the repository.

IIIWork completed

What changed, with the source for each.

  • Moved the site from Wix to GitHub Pages on the apex domain, with HTTPS
  • Rewrote 93 internal links to one canonical form
  • Gave every page a self-referencing canonical tag that matches the sitemap
  • Kept old .html addresses as noindex stubs that point to the new URLs
  • Shared one Person identifier for the founder with kenashe.ai
  • Added a dependency-free test suite that runs on every push

From the decision log

  1. 1Decision D1: retire Wix and serve a hand-built static site from GitHub Pages, on the company's own domain.
  2. 2Decision D4: every page linked to index.html three times, which told Google the duplicate was real. All 93 links now use one canonical form.
  3. 3Decision D11: old .html addresses stay as small noindex pages that point to the new URL, because a static host cannot redirect.
  4. 4Decision D8: a dependency-free test suite runs on every push, checking links, canonicals, the sitemap, and metadata.

VCurrent status

VILessons

What we would do the same way again.

  1. On a static host, canonical tags and consistent internal links do the job redirects cannot.
  2. Blocking duplicate URLs in robots.txt backfires: a blocked page cannot be crawled, so its canonical tag is never read.
  3. Writing decisions down makes the next change faster, whether a person or an agent makes it.
